# Как понять, запомнить и написать этот проект сам

Не учи файлы наизусть. Запомни **одну картинку и пять глаголов**.

```
газеты с улицы          вырезать рекламу        разложить по языкам
     RSS          →         HTML           →         language
                                                          ↓
              Parquet  ←  выкинуть копии
             (коробки)         дубли
```

Пять глаголов:

1. **получить**
2. **очистить**
3. **пометить язык**
4. **схлопнуть дубли**
5. **сохранить**

Если на бумаге можешь нарисовать эти пять стрелок — ты уже напишешь код.

---

## Аналогия, которая держит всё в голове

Ты библиотекарь.

- Привезли мешки газет из разных киосков (**RSS / News API**).
- В газетах картинки, рамки, ссылки — для полок это мусор (**очистка HTML**).
- Русские и английские газеты на разные стеллажи (**язык**).
- Одна и та же статья приехала трижды (**дубли**).
- В архив кладёшь не кипы бумаги, а аккуратные коробки (**Parquet**).
- Потом читатель спрашивает «что случилось с батареями?» — ты достаёшь нужные куски и отдаёшь человеку, который умеет связно отвечать (**RAG**).

Пайплайн = работа библиотекаря. RAG = читальный зал.

---

## Зачем каждый шаг (это спрашивают на собесе)

### 1. Получение

RSS — лента в XML. Ты не парсишь XML руками, это делает `feedparser`.

На выходе всегда `list[Article]`. Поэтому RSS и News API — просто разные входы
в одну трубу. Если завтра добавишь Telegram — пайплайн ниже fetch не трогаешь.

Запомни: **контракт важнее источника**. Контракт здесь — `Article`.

### 2. Очистка HTML

В RSS текст часто такой:

```html
<p>Курс вырос на 3%.<a href="...">Читать далее</a></p>
```

Для человека и для модели нужно:

```
Курс вырос на 3%. Читать далее
```

`BeautifulSoup.get_text()` снимает теги, `html.unescape` чинит `&nbsp;`,
регулярка схлопывает пробелы. Три действия, не «магия NLP».

### 3. Язык

`langdetect` смотрит на буквы и характерные слова, возвращает `en` / `ru` / ...

Делаем это один раз при сборке датасета. В Parquet появляется колонка `language`.
Потом `df[df.language == "ru"]` — и RAG не мешает языки.

### 4. Дубли

Два дешёвых ключа покрывают 90% случаев:

| ключ | смысл |
|---|---|
| URL без `/` на конце, в нижнем регистре | та же страница |
| заголовок в lowercase без пунктуации | та же новость с другого сайта |

Эмбеддинги для дедупа — следующий уровень, не первый. На собесе скажи это сам:
«сначала точные ключи, потом семантика, если точных не хватит».

### 5. Parquet

Не JSON и не CSV.

- CSV ломается на запятых и кавычках внутри новости
- JSON тяжёлый и его неудобно фильтровать по колонкам
- Parquet хранит колонки отдельно, жмется, читается кусками

Для датасета новостей это правильный формат «положили и забыли».

## RAG на пальцах

Модель не читает весь интернет в момент ответа. Схема такая:

```
вопрос человека
    → найти похожие куски текста (retrieval)
    → подставить их в промпт
    → модель отвечает, опираясь на эти куски (generation)
```

Чтобы поиск работал, тексты должны быть:

- без HTML
- без копий
- с метаданными (url, дата, язык)
- порезанными на чанки (см. `rag_preview.py`)

Этот проект делает заготовки. Чанки / эмбеддинги / векторная БД — следующий репозиторий.

## Как написать это с нуля за вечер

Открой пустую папку и иди сверху вниз. Не прыгай.

### Минута 1. Нарисуй

```
fetch → clean → language → dedup → parquet
```

### Минута 2. Контракт

```python
@dataclass
class Article:
    title: str
    url: str
    text: str
    source: str
    published: str | None = None
    language: str | None = None
```

Если структура карточки ясна — остальное наращивается вокруг неё.

### Минута 3–20. Пять функций

Пиши сигнатуры до реализации:

```python
def fetch_all(feeds) -> list[Article]: ...
def clean_html(raw: str) -> str: ...
def detect_language(text: str) -> str | None: ...
def drop_duplicates(articles: list[Article]) -> list[Article]: ...
def save_parquet(articles, path) -> None: ...
```

Потом заполни каждую 10–20 строками. Не больше. Если функция расползлась —
ты смешал два шага.

### Минута 21. Склейка

```python
articles = fetch_all(feeds)
for a in articles:
    a.text = clean_html(a.text)
    a.language = detect_language(a.text)
articles = drop_duplicates(articles)
save_parquet(articles, path)
```

Это и есть `pipeline.py`. Если ты можешь написать этот кусок по памяти —
проект у тебя в голове.

## Мини-шпаргалка библиотек

| шаг | библиотека | что она делает одной фразой |
|---|---|---|
| RSS | `feedparser` | XML-лента → список записей |
| HTTP | `requests` | скачать с User-Agent и timeout |
| HTML | `beautifulsoup4` | теги → текст |
| язык | `langdetect` | текст → `en`/`ru` |
| таблица | `pandas` | список словарей → DataFrame |
| файл | `pyarrow` | DataFrame → `.parquet` |

## Что сказать, если спросят «как улучшить»

Говори по слоям, не «добавлю нейросеть».

1. Ходить в полную статью по URL, не только RSS-анонс
2. Дедуп по simhash / эмбеддингам заголовка
3. Нормализация дат в UTC и фильтр «старше N дней»
4. Идемпотентный запуск: не писать заново, а дописывать новые URL
5. Чанкинг + эмбеддинги + Qdrant/Chroma и простой CLI «задайте вопрос»

Пункты 1–4 остаются в этом репозитории. Пункт 5 — уже продукт поверх датасета.
