# News ETL → Parquet (RAG-ready)

Небольшой пайплайн новостей для портфолио:

**RSS → очистка HTML → язык → удаление дублей → Parquet**

Датасет потом можно скармливать RAG: в файле уже чистый текст и метаданные.

## Зачем это работодателю

Это не «скрипт скачал RSS». Это ETL:

1. Сбор из нескольких источников (RSS, опционально News API)
2. Очистка грязного HTML
3. Языковая разметка
4. Дедупликация
5. Колоночное хранение, удобное для pandas / DuckDB / эмбеддингов

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python run.py
python -m pytest
python rag_preview.py
```

Результат: `data/news.parquet`

Колонки: `title`, `url`, `text`, `source`, `published`, `language`

News API не обязателен. Если есть ключ:

```bash
export NEWSAPI_KEY=...
python run.py
```

## Как устроен код

Читать в таком порядке:

1. `LEARN.md` — зачем каждый шаг и как написать это сам
2. `pipeline.py` — вся карта, 5 вызовов подряд
3. `steps/` — по одному файлу на стрелку из задания
4. `models.py` — одна карточка новости на весь проект

## Что можно рассказать на собеседовании

- Почему Parquet, а не JSON/CSV
- Почему дедуп по URL + нормализованному заголовку, а не сразу эмбеддингами
- Почему язык определяется до индексации, а не в RAG-запросе
- Как этот файл становится чанками и эмбеддингами (см. `rag_preview.py`)
